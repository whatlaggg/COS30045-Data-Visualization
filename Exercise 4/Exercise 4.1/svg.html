Step 2: Understanding the SVG Coordinate System

Unlike traditional Cartesian mathematics where the $Y$-axis increases upward, the SVG coordinate space begins at the top-left corner $(0, 0)$:

  • X-axis: Extends from left to right ($0 \rightarrow \text{viewBox width}$).
  • Y-axis: Extends from top to bottom ($0 \rightarrow \text{viewBox height}$).
  • Transformations: Group transformations (translate(dx, dy)) create localized sub-coordinate origins relative to the parent canvas.

Step 4: The Group Element (<g>) and Transformations

In SVG, repeating identical elements (such as multiple windows) by hand-coding absolute pixel coordinates for every sub-pane is error-prone. The <g> element solves this by:

1. Cascading Styles

Defining attributes like fill="#E0F2FE" and stroke="#0369A1" on the parent <g> automatically propagates them to all child rectangles and lines without redundant markup.

2. Modular Positioning

Both windows use the exact same internal layout (0 to 45px). Using transform="translate(170, 225)" and transform="translate(285, 225)" shifts the entire window assembly as a single atomic unit.

SVG Window Group Implementation (Step 4)
<!-- Parent Group: Defines shared window palette and stroke styling -->
<g id="window-system" fill="#E0F2FE" stroke="#0369A1" stroke-width="3" stroke-linejoin="round">
  
  <!-- Left Window: Positioned via translate offset (x=170, y=225) -->
  <g transform="translate(170, 225)">
    <rect width="45" height="45" rx="3"/>
    <line x1="22.5" y1="0" x2="22.5" y2="45" stroke="#0369A1" stroke-width="2"/>
    <line x1="0" y1="22.5" x2="45" y2="22.5" stroke="#0369A1" stroke-width="2"/>
  </g>

  <!-- Right Window: Identical internal geometry, translated to (x=285, y=225) -->
  <g transform="translate(285, 225)">
    <rect width="45" height="45" rx="3"/>
    <line x1="22.5" y1="0" x2="22.5" y2="45" stroke="#0369A1" stroke-width="2"/>
    <line x1="0" y1="22.5" x2="45" y2="22.5" stroke="#0369A1" stroke-width="2"/>
  </g>

</g>
